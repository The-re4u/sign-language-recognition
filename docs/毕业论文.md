## ABSTRACT

Sign language is the primary communication modality for over 70 million deaf individuals worldwide. For native sign language users, typing on a keyboard requires a cognitively demanding conversion from sign language concepts to Chinese grammatical structures and then to character-level encoding — a process that imposes high cognitive load and low expression efficiency. For congenitally deaf and elderly deaf populations whose sole proficient language is sign language, text-based input is functionally equivalent to communicating in a foreign language. It is therefore necessary to develop an approach that enables deaf individuals to communicate directly through their native gestural modality.

This thesis presents a lightweight, multimodal real-time sign language recognition system based on the MediaPipe visual pipeline. The system introduces a novel dual-hand combinatorial encoding protocol as its core interaction paradigm: the non-dominant hand selects one of seven semantic layers through mode gestures, while the dominant hand specifies meaning through one of ten content gestures, producing 70 unambiguous semantic slots from only 15 base gestures. The system adopts a seven-layer pipeline architecture that processes the complete workflow from camera capture to natural Chinese sentence output: (1) Perception Layer — MediaPipe HandLandmarker extracts 21 three-dimensional hand keypoints at 128px input resolution, with first-frame wrist normalization for distance invariance; (2) Feature Extraction Layer — SpatialGCN (0.15M parameters) encodes hand skeletal topology through graph convolutions with an auxiliary angle encoder, MotionEncoder (0.04M) fuses optical flow histograms with keypoint velocity fields, and LightweightVisualEncoder (MobileNetV3-Small frozen backbone) extracts ROI visual texture, integrated through CrossModalFusion (2-layer Transformer Encoder, 1.9M) into a 256-dimensional unified representation; (3) Temporal Modeling Layer — SlowFast TCN (dual-pathway temporal convolution, 0.7M) captures long-range semantics via the Slow pathway and preserves fine-grained dynamics via the Fast pathway, with temporal mean pooling and cross-entropy loss for sequence-level classification; (4) Rule-Based Recognition Layer — a geometric decision tree classifies 17 gestures deterministically using finger joint angles (>165° extension threshold), incorporating PIP joint error compensation and satisfying Explainable AI (XAI) requirements; (5) Semantic Parsing Layer — a SentenceRecorder state machine manages the sentence-level recording lifecycle, while the TemporalSemanticParser resolves gesture token sequences into semantic chains via longest-suffix matching, with symmetric dual-hand control gestures for undo and separator functions; (6) LLM Enhancement Layer — DeepSeek API integration provides semantic reassembly and natural language polishing across translation and AI triage modes, with a four-level graceful degradation strategy; (7) UI Presentation Layer — a Vue 3 single-page application with FastAPI WebSocket backend supports real-time camera input, Canvas 21-point skeleton rendering, gesture confidence display, and one-click DL/Rule mode switching. The total trainable deep learning parameters are within 2.8 million, well below the 10M task book budget, enabling CPU-only real-time inference.

To validate the proposed system, we conducted extensive experiments on a self-collected dataset of 1,311 samples with systematic domain randomization covering lighting, angle, and distance variations. The multimodal deep learning model achieved 82.8% test accuracy, representing a 51.7 percentage point improvement over the rule-based geometric classifier on the same real-user data, with 5-fold cross-validation confirming consistent performance (84.1% ± 1.5%). Ablation experiments established spatial graph topology as foundational (76.6pp contribution), with motion dynamics (31.6pp) and visual texture (9.6pp) providing significant and complementary contributions. The system achieved 31.7 FPS hand detection speed, exceeding the real-time requirement, with 32.1 ms end-to-end processing latency, validated as stable across 92 recording sessions.

Based on the proposed method, a complete sign language recognition prototype system was developed. Its features include real-time sign language translation, AI-assisted triage consultation with multi-turn symptom inquiry and department recommendation, one-click switching between the explainable rule engine and the deep learning model, and a scene-transferable architecture where semantic mappings, chain rules, and language model prompts are defined through JSON configuration files — enabling migration to banking, airport, smart home, and government service scenarios without code modification. This work demonstrates that treating sign language gestures as linguistic tokens in a pipeline culminating in large language model-based semantic reassembly can bridge the gap between isolated gesture classification and natural sentence output, providing a feasible solution for accessible communication in healthcare and public service settings.

# CHAPTER 1: INTRODUCTION

## 1.1 Background

Sign language is the primary communication modality for over 70 million deaf individuals worldwide, according to the World Federation of the Deaf. In China alone, approximately 20 million people experience hearing impairment, with Chinese Sign Language (CSL) serving as their native linguistic system. However, a profound communication barrier persists in daily life: the vast majority of hearing individuals do not understand sign language, and existing assistive technologies predominantly rely on text-based input methods that are fundamentally misaligned with the cognitive and linguistic patterns of deaf users.

For native sign language users, typing on a keyboard requires a cognitively demanding double conversion process: first, translating from sign language concepts to Chinese grammatical structures (two languages with fundamentally different word orders and grammatical features), and then encoding the Chinese grammar into character-level input through Pinyin or stroke-based input methods. This three-stage cognitive pipeline imposes significant mental load and reduces communication efficiency to a fraction of natural sign language expression speed. This approach both violates their linguistic autonomy and introduces systematic expressive distortion, as the grammatical structure of sign language (which is spatial, simultaneous, and highly iconic) does not map cleanly onto the linear, sequential structure of written Chinese.

The technological landscape has shifted dramatically in recent years. Markerless human pose estimation frameworks, particularly Google MediaPipe, have democratized access to real-time hand tracking. MediaPipe Hands detects 21 three-dimensional keypoints from a single RGB image at over 30 frames per second on commodity hardware, without requiring depth sensors, special gloves, or calibrated multi-camera setups. This breakthrough has opened the possibility of practical sign language recognition systems that can operate on ordinary laptop webcams — a critical requirement for real-world accessibility applications where specialized hardware is economically infeasible.

Wagh et al. [1] provided the first proof-of-principle clinical validation that single-camera MediaPipe tracking can extract clinically meaningful kinematic outcomes — including palm speed and Bivariate Variable Error (BVE) — from video data in stroke populations. Hamaguchi et al. [4] verified criterion-related validity against gold-standard marker-based systems, reporting correlation coefficients of r = 0.72–0.82 in patient populations with mean absolute deviation of 2.46 degrees, reducible to 0.81 degrees with Kalman filtering. Sprague et al. [3] identified the PIP (proximal interphalangeal) joint as the primary source of tracking error, with fast hand motion further degrading accuracy — findings that directly inform the error compensation strategies in this thesis.

Despite these advances in perception technology, most existing sign language recognition (SLR) systems share a critical limitation: they focus on isolated word classification. The research community has largely treated SLR as a computer vision problem — given an image or video clip, classify which word is being signed. Furthermore, the integration of large language models (LLMs) for semantic interpretation of gesture sequences remains a largely unexplored direction, despite the rapid advancement of LLM capabilities in recent years with models like DeepSeek-V2 [25] demonstrating strong performance in Chinese-language medical dialogue tasks.

This thesis addresses both gaps simultaneously: it proposes a complete pipeline that treats gestures as linguistic tokens rather than mere visual patterns, and it integrates an LLM layer that converts raw gesture sequences into natural, contextually appropriate Chinese sentences. The system is validated in a hospital triage scenario — a real-world communication context where accurate, efficient information transfer between a deaf patient and medical staff is critical.

## 1.2 Purpose and Significance

### 1.2.1 Gap Analysis of Existing Solutions

Five categories of assistive communication technologies are examined below.

**Professional Sign Language Interpreters:** China has approximately 20 million hearing-impaired individuals but only approximately 10,000 certified interpreters (2,000:1 ratio). **Text-Based Communication:** Typing on mobile phones (20–30 words per minute versus 120–180 signs per minute for natural sign language) imposes the double conversion burden and undermines face-to-face engagement essential to medical consultation.

**Wearable Glove-Based Systems:** Despite high laboratory accuracy (>95%), glove-based systems face practical barriers: expensive hardware, physical discomfort, social stigma as a visible "disability marker," and maintenance requirements.

**Camera-Based Academic Systems:** Recent systems (SignGemma 4B parameters, various ST-GCN/Transformer architectures) share three limitations: GPU-dependent inference, output limited to class labels rather than communicable sentences, and fixed vocabularies without scene customization mechanisms.

## 2.1 MediaPipe Hand Tracking and Clinical Validation

Google MediaPipe Hands represents a significant advance in markerless hand pose estimation, building on decades of progress in computer vision for human pose tracking. The framework employs a two-stage machine learning pipeline: a palm detection model identifies the approximate hand region in the image, followed by a hand landmark model that regresses 21 three-dimensional keypoint coordinates within the detected region. This anatomical coverage enables comprehensive hand pose reconstruction from a single RGB image without depth sensors.

The framework operates in real time on commodity hardware, achieving detection speeds exceeding 25 frames per second on CPU through the XNNPACK delegate. This performance profile makes it uniquely suitable for practical sign language recognition applications, where dedicated GPU hardware may not be available and low latency is critical for natural interaction.

Wagh et al. [1] provided the foundational methodological reference for this work. Their proof-of-principle study demonstrated that single-camera MediaPipe tracking can extract clinically meaningful kinematic outcomes — including palm speed and Bivariate Variable Error (BVE) — from video data in stroke populations. Specifically, the 17-dimensional kinematic feature set (including palm speed, fingertip velocity, inter-finger coordination, and trajectory stability) was designed following the measurement framework validated in Wagh et al.'s work.

## 2.2 Graph Convolutional Networks for Skeleton-Based Recognition

Graph Convolutional Networks (GCNs) extend the convolution operation from regular grid structures (such as image pixels) to irregular graph structures (such as skeletal joints connected by bones). This generalization is particularly well-suited to hand skeleton data, where the 21 keypoints naturally form a graph with bone connections as edges and joint coordinates as node features.

The foundational work in this area is the Spatial Temporal Graph Convolutional Network (ST-GCN) proposed by Yan et al. [6] at AAAI 2018. ST-GCN models the human skeleton as a spatio-temporal graph G = (V, E) where nodes V represent body joints at each time step and edges E represent both spatial connections (bones connecting joints within a frame) and temporal connections (the same joint across consecutive frames). The spatial graph convolution operation at layer l for node i aggregates features from its neighboring nodes:

h_i^(l+1) = σ( Σ_{j∈N(i)} W^(l) · h_j^(l) / c_ij )

where each node aggregates features from its skeletal neighbors through learnable weights, and c_ij is a normalization constant. This message-passing mechanism, combined with temporal 1D convolutions along the time axis, enables joint modeling of spatial hand topology and motion dynamics.

Since ST-GCN, the research community has developed numerous enhancements specifically for sign language recognition. Zhou et al. [7] at LREC-COLING 2024 proposed a multimodal spatio-temporal GCN model with gating mechanisms for isolated sign recognition, incorporating both skeleton data and handshape features. Liu et al. [8] introduced Asymmetric Multi-branch GCN (AM-GCN) for skeleton-based SLR, achieving 96.27% on AUTSL and 98.20% on CSL datasets through dilated convolutions in asymmetric branches to expand the receptive field. The hand-aware GCN (HA-GCN) [9] explicitly models hand skeletal topology through two adaptive hand sub-graphs: a structured hand graph based on anatomical bone connections and a parameterized hand graph learned from data, achieving 96.82% on AUTSL and 99.63% on the INCLUDE dataset.

Huang et al. [10] proposed synchronized and fine-grained head mechanisms for skeleton-based ambiguous action recognition, addressing cases where similar skeleton configurations map to different semantic actions — a problem directly analogous to the Two versus Victory or Four versus Nine disambiguation challenges in this system.

## 2.3 Temporal Convolutional Networks and SlowFast Architecture

Temporal modeling of gesture sequences requires architectures that can capture both fine-grained frame-to-frame dynamics and long-range temporal context spanning complete gesture phrases. Two families of approaches dominate the literature: recurrent neural networks (RNNs, including LSTM and GRU variants) and temporal convolutional networks (TCNs).

Temporal Convolutional Networks, introduced by Lea et al. [12] at CVPR 2017 for action segmentation and detection, use causal convolutions with dilated kernels to capture long-range temporal dependencies. Unlike recurrent networks, TCNs offer several decisive advantages: (1) parallel computation across time steps, (2) no vanishing/exploding gradient problems through the temporal dimension, (3) precise control over receptive field size through kernel size and dilation rate selection, and (4) easier export to inference formats (ONNX) since the computation graph is purely feed-forward.

The GCAR model [13] demonstrated the parameter efficiency of TCN-based approaches for sign language, achieving 90.31% accuracy on WLASL with only 0.69M parameters through a two-stream multistage graph convolution with attention and residual connection. This result — competitive accuracy with less than 1M parameters — validates the TCN paradigm for resource-constrained sign language recognition.

The SlowFast architecture, originally proposed by Feichtenhofer et al. [11] at ICCV 2019 for video action recognition, introduced a key insight: visual semantics in video change slowly (a hand pose persists over many frames) while fine-grained motion occurs quickly (finger transitions happen between consecutive frames). Rather than processing all frames at a single temporal resolution, SlowFast employs dual pathways operating at different frame rates with lateral connections transferring information from the Fast pathway to the Slow pathway.

This dual-temporal-resolution design was adapted in this thesis as a SlowFast TCN for gesture sequence modeling. The key adaptations from video action recognition to gesture recognition are: (1) replacing 3D spatial-temporal convolutions with 1D temporal convolutions (since spatial features are already extracted by the GCN upstream), (2) using causal convolutions to prevent future-frame leakage in real-time inference, and (3) reducing channel dimensions to maintain the sub-1M parameter budget. SF-TPGR [15] applied SlowFast to traffic police gesture recognition using skeleton heatmaps, achieving 79ms inference with 98.1% accuracy — demonstrating that SlowFast generalizes effectively beyond its original video action recognition domain.

## 2.4 Multimodal Fusion and Transformer Attention

The fusion of multiple modality streams — spatial geometry from keypoints, temporal dynamics from motion, and appearance features from RGB images — requires an architecture that can learn which modality to trust under different conditions. Early fusion approaches (simple concatenation) treat all modalities equally, failing to adapt when one modality is degraded. Late fusion approaches (separate classifiers with voting) miss cross-modal interactions entirely. Attention-based fusion occupies a middle ground, enabling the model to dynamically weight modalities based on input quality.

Transformer architectures, introduced by Vaswani et al. [21] in "Attention is All You Need" at NeurIPS 2017, have become the dominant paradigm for multimodal fusion due to their ability to model pairwise interactions between all input tokens through multi-head self-attention. The multi-head self-attention mechanism enables each modality token to attend to information from all other modalities through learned query-key-value projections.

MSGCN [22] applied multimodal fusion to sign language recognition by combining skeleton-based GCN features with RGB-based deformable 3D convolutional features through a gating mechanism. Recent work [23] on multi-modal fusion with Transformer-enhanced learning demonstrated real-time continuous sign language recognition with low-latency inference specifically optimized for edge devices. Cross-attentive multi-cue fusion [24] extended this direction by explicitly modeling which visual cues contribute most to each recognition decision.

In this thesis, the CrossModalFusion module (Section 3.3.4) adapts the Transformer fusion paradigm with a key innovation: learnable modality type embeddings. Beyond the standard position embeddings used in Transformer architectures, each modality token is augmented with a learned embedding that encodes its source (visual, spatial, or motion). This enables the self-attention mechanism to distinguish not just which token to attend to, but which modality that token represents.

## 2.6 Sign Language Recognition: From Classification to Semantic Understanding

The evolution of sign language recognition research reflects a broader trajectory in artificial intelligence: from hand-crafted features to deep learning, from isolated classification to sequential modeling, and — most recently — from pattern recognition to semantic understanding. Bragg et al. [28] provided a landmark interdisciplinary perspective on SLR, generation, and translation, identifying key priorities: (1) the Deaf community prioritizes communicative function over academic benchmark performance; (2) isolated word recognition does not address real communication needs; (3) integration of linguistic knowledge is essential for practical systems.

Li et al. [29] introduced WLASL (Word-Level American Sign Language), a dataset of over 2,000 ASL word classes with 21,083 video samples, which has become the standard benchmark for isolated SLR. Rastgoo et al. [30] provided a comprehensive survey of deep learning approaches for sign language recognition, identifying the trend toward skeleton-based methods and the need for continuous recognition.

The critical gap that this thesis addresses is the integration of LLMs for semantic interpretation. Most existing SLR systems stop at classification — they output a word label and consider the task complete. But communication does not end at word recognition. Words must be assembled into sentences with proper grammar, adapted to conversational context, and expressed with appropriate tone. DeepSeek-V2 [25] and medical LLM applications [26][27] have demonstrated that LLMs can perform these functions for text-based medical dialogue. Extending this capability to gesture-based input — where the LLM receives not well-formed text but a sequence of semantic tokens with potential gaps, repetitions, and errors — represents a novel integration.

## 2.7 Research Trend Analysis and Positioning

The literature reviewed in this chapter reveals a clear evolutionary trajectory in sign language recognition research over the past decade, progressing through four stages: (1) **Isolated Classification** (2015–2019) — treating SLR as a visual pattern recognition problem, exemplified by early CNN-based approaches and the WLASL benchmark [29]; (2) **Skeleton-Based Recognition** (2018–2022) — leveraging pose estimation (OpenPose, MediaPipe) to extract skeletal keypoints and applying GCN/TCN architectures [6][8][12] for more robust, background-invariant recognition; (3) **Multimodal Fusion** (2022–2024) — combining skeleton, RGB, depth, and optical flow modalities through attention mechanisms and Transformer architectures [7][22][23]; and (4) **Semantic Understanding** (2024–present) — the emerging recognition that classification accuracy alone is insufficient, and that practical SLR systems must bridge the gap from gesture labels to communicable language through LLM integration [25][26][27] and scene-contextualized semantic parsing.

The proposed system in this thesis is positioned at the transition from Stage 3 to Stage 4. It inherits the multimodal fusion paradigm (Stage 3: GCN + Visual + Motion Transformer-fused) but extends it with two contributions that push toward Stage 4: (a) the dual-hand combinatorial encoding protocol, which treats gestures as linguistic tokens in a compositional semantic system, and (b) the LLM enhancement layer, which converts raw token sequences into contextually appropriate natural language. This positioning — leveraging mature multimodal perception while pioneering LLM-enhanced semantic output — represents the central contribution of this thesis within the broader research trajectory.

# CHAPTER 3: PROPOSED METHOD FOR SIGN LANGUAGE RECOGNITION

This chapter presents the core technical contribution of the thesis: a seven-layer pipeline that converts raw video frames from a commodity RGB camera into natural Chinese sentences. Each layer is described in detail, with specific attention to architectural improvements over baseline approaches and design rationale grounded in the literature reviewed in Chapter 2.

## 3.1 Overall Architecture

The proposed system adopts a seven-layer pipeline architecture, processing video frames sequentially from camera capture to natural language output. Figure 3-1 provides a visual overview of the complete pipeline. The layers are organized as follows:

**Layer 1 — Perception (Section 3.2):** MediaPipe HandLandmarker extracts 21 three-dimensional hand keypoints from each video frame at 128-pixel input resolution. Wrist-relative normalization ensures distance invariance across users. The detector operates on CPU via the XNNPACK delegate, achieving 31.7 FPS.

**Layer 2 — Feature Extraction (Section 3.3):** Three parallel encoders process the keypoint data into complementary feature representations. SpatialGCN (0.15M parameters) encodes hand skeletal topology through graph convolutions with an auxiliary angle encoder. LightweightVisualEncoder (0.15M trainable, MobileNetV3-Small backbone frozen) extracts RGB texture features from 96×96 hand ROI crops. MotionEncoder (0.04M) captures inter-frame dynamics through keypoint velocity fields and optical flow histograms. The three modality embeddings are integrated through CrossModalFusion (1.9M), a 2-layer Transformer Encoder with learnable modality type embeddings.

**Layer 3 — Temporal Modeling (Section 3.4):** The SlowFast TCN (0.7M) processes sequences of fused features through dual temporal pathways. The Slow pathway (kernel 7, dilations [1,2,4], receptive field 43 frames ≈ 1.7 seconds) captures long-range gesture semantics. The Fast pathway (kernel 3, dilations [1,1,2,2]) preserves fine-grained finger dynamics. Lateral convolutions transfer information from Fast to Slow. Temporal mean pooling followed by cross-entropy loss converts frame-level logits to a single sequence-level class prediction.

**Layer 4 — Rule-Based Recognition (Section 3.5):** A geometric decision tree with clinically validated thresholds provides both a production recognition path and an XAI-compliant fallback. Finger extension is determined by MCP-PIP-DIP joint angles exceeding 165 degrees. PIP/MCP dual-channel verification applies confidence penalties for inconsistent detections.

**Layer 5 — Semantic Parsing (Section 3.6):** The core innovation — a dual-hand combinatorial encoding protocol. The non-dominant hand selects one of seven semantic layers. The dominant hand selects a specific meaning within that layer. Symmetric dual-hand control gestures provide undo-word, undo-sentence, and manual separator functions. The SentenceRecorder state machine manages the recording lifecycle. The TemporalSemanticParser resolves gesture token sequences into semantic chains via longest-suffix matching.

**Layer 6 — LLM Enhancement (Section 3.7):** The DeepSeek Chat API provides two operational modes. In translation mode, raw gesture token sequences are sent with a hospital communication system prompt for word reordering, sentence completion, and tone customization. In triage mode, multi-turn symptom inquiry leads to department recommendation. A four-level graceful degradation strategy ensures system availability.

**Layer 7 — UI Presentation:** A Vue.js 3.5 single-page application communicates with the FastAPI backend via WebSocket at 25 FPS. Real-time HTML5 Canvas rendering overlays the 21-keypoint hand skeleton (color-coded: blue left, green right) on the live camera feed. Gesture cards display recognition results with confidence percentages. The semantic output panel shows the current token buffer with state-dependent color coding. One-click toggles switch between DL/Rule mode and translation/triage mode.

A key architectural principle is the separation between scene-agnostic and scene-specific layers. Layers 1 through 4 (perception, feature extraction, temporal modeling, rule recognition) are completely independent of the application scenario — they recognize hand gestures regardless of what those gestures mean. Layers 5 and 6 (semantic parsing, LLM enhancement) are scene-configurable through JSON files that define gesture-to-meaning mappings, semantic chain rules, and LLM system prompts. This separation means that migrating the system from hospital triage to banking, airport information, smart home control, or government services requires only replacement of configuration files — the underlying gesture recognition code remains unchanged.

## 3.2 Perception Layer: MediaPipe Hand Keypoint Detection

The perception layer converts raw RGB video frames into structured hand keypoint data. This conversion must be fast (to meet real-time requirements), accurate (to provide reliable input to subsequent classifiers), and robust (to handle varying lighting, hand orientations, and distances).

### 3.2.1 Input Processing

Each frame received from the camera (original resolution typically 640×480 pixels, JPEG-compressed for WebSocket transmission at 25 FPS) is decoded and downscaled. The longer edge is resized to 128 pixels while maintaining the aspect ratio. This resolution was chosen empirically: 160 pixels (the previous setting) provided marginally higher keypoint accuracy but at approximately 34ms detection latency, while 128 pixels reduces detection to approximately 31.5ms with negligible accuracy loss. The trade-off between resolution and speed is particularly important for CPU-only deployment.

### 3.2.2 MediaPipe HandLandmarker Configuration

The HandLandmarker is configured with the following parameters, chosen based on the clinical validation literature reviewed in Section 2.1:

- **num_hands = 2**: Both hands are detected simultaneously, enabling the dual-hand encoding protocol.
- **min_detection_confidence = 0.4**: Reduced from the default 0.5 to maintain hand tracking persistence during rapid movements and partial occlusions. The literature [2][3] indicates that PIP joint tracking error increases under high-speed motion; lowering the detection threshold prevents premature hand loss at the cost of occasional low-confidence detections, which are filtered by downstream confidence checks.
- **min_tracking_confidence = 0.35**: Further reduced from 0.5 to maintain tracking continuity across frames.

### 3.2.3 Keypoint Normalization

Raw keypoint coordinates from MediaPipe are in normalized image coordinates (range [0, 1] relative to image width and height). To achieve distance and scale invariance, first-frame wrist normalization is applied. For each hand, the wrist keypoint (index 0) is used as the reference point, and the palm size is estimated as the Euclidean distance between the wrist and the middle finger MCP joint (index 9):

palm_scale = ‖ kp_9 − kp_0 ‖

kp'_i = (kp_i − kp_0) / palm_scale

This maps the hand to a canonical coordinate frame invariant to camera distance and user position.

### 3.2.4 Handedness Sorting

MediaPipe provides handedness classification (Left/Right) for each detected hand. Since raw detection order varies depending on which hand enters the frame first, the system explicitly sorts detected hands by their MediaPipe handedness label to ensure consistent left-hand-as-mode, right-hand-as-content assignment. When only one hand is detected, persistent mode memory retains the previously established mode for 1.5 seconds.

## 3.3 Feature Extraction Layer: Multi-Modal Encoding

The feature extraction layer transforms the 21 normalized keypoint coordinates and the original video frame into rich, complementary feature representations. Three parallel encoders produce modality-specific embeddings, which are then integrated through a Transformer-based fusion module.

### 3.3.1 Spatial Graph Convolutional Network (SpatialGCN)

The SpatialGCN models the hand skeleton as a graph G = (V, E) where the node set V consists of the 21 keypoints and the edge set E consists of 23 bone connections (19 direct bone edges plus 4 functional edges connecting the bases of adjacent fingers). Each node i has an initial feature vector h_i^(0) = [x_i, y_i, z_i] representing its normalized 3D coordinates.

The graph convolution operation at layer l aggregates features from each node's neighbors N(i):

h_i^(l+1) = ReLU( W^(l) · Σ_{j∈N(i)∪{i}} h_j^(l) / √(|N(i)|+1) )

Three graph convolution layers are stacked with residual connections, progressively increasing the feature dimension from 3 (input coordinates) through 64 and 128 to 256 (output embedding). A residual connection at each layer adds the input features to the output, enabling gradient flow through deep layers.

**Auxiliary Angle Encoder:** A key improvement over standard GCN architectures is the auxiliary angle encoder that computes 10 inter-joint angles directly from the keypoint coordinates. For each finger (thumb through pinky), the MCP-PIP-DIP angle is computed using the law of cosines:

θ = arccos( (a² + b² − c²) / (2ab) )

where a, b, c are the Euclidean distances between the three joint points. The 10 angles (2 per finger: MCP-PIP-DIP for the main joint chain, and the inter-finger spread angle between adjacent fingers) are encoded through a small fully-connected network (10→32→64) to produce a 64-dimensional geometric prior. This feature is concatenated with the GCN output and projected to 256 dimensions.

The auxiliary angle encoder addresses a limitation of pure GCNs: geometric relationships that are anatomically obvious must otherwise be learned from data. By explicitly encoding joint angles, the model receives strong geometric priors that accelerate learning on limited data [4]. The complete SpatialGCN module contains approximately 0.15M parameters.

### 3.3.2 Lightweight Visual Encoder

While keypoint coordinates capture the geometric configuration of the hand, they discard all photometric information — skin texture, shadows, contours, and visual context. The LightweightVisualEncoder complements the geometric features with appearance-based information.

The encoder uses a MobileNetV3-Small backbone [31], a state-of-the-art lightweight convolutional network designed through neural architecture search for mobile and edge deployment. The backbone was pre-trained on ImageNet, providing strong general-purpose visual feature extraction. The classifier head is removed, exposing the 576-dimensional feature vector from the global average pooling layer. A trainable two-layer MLP projection head (576→512→512, with ReLU activation and Dropout(0.1) between layers) maps these features to the final 512-dimensional visual embedding.

The backbone's parameters are frozen at ImageNet pre-trained values to prevent overfitting on the limited 1,311-sample dataset. The trainable projection head (approximately 0.15M parameters) adapts generic visual features to the gesture classification task.

**Input Preparation:** A 96×96 pixel ROI is cropped around the detected hand keypoints. The crop region is computed as the bounding box of all 21 keypoints expanded by a 25-pixel margin in each direction. The crop is resized to exactly 96×96 pixels using bilinear interpolation.

**Zero-Input Handling:** Synthetic training samples lack corresponding ROI images. For these samples, the encoder receives a tensor of zeros. A dedicated early-exit path checks `x.abs().sum() == 0` at the start of the forward pass and returns a zero vector immediately, bypassing the MobileNetV3 backbone entirely. The model is trained with a mixture of real ROI samples and zero-input synthetic samples, learning to rely more heavily on geometric and motion features when visual information is absent.

### 3.3.3 Motion Encoder

The MotionEncoder captures inter-frame dynamics, including subtle within-pose movements (tremors, adjustments) that provide discriminative information beyond static spatial features.

Two input streams are computed from consecutive frame keypoints:

1. **Keypoint Velocity Field (63 dimensions):** For each of the 21 keypoints, the 2D displacement vector (dx, dy) between frames t−1 and t is computed. Additionally, the magnitude of the displacement √(dx²+dy²) is included for each keypoint, yielding 21×3 = 63 dimensions.

2. **Optical Flow Histogram (128 dimensions):** The 21 keypoint displacement vectors are aggregated into a flow histogram. The first 21 bins accumulate displacement magnitudes per keypoint. The remaining 107 bins form a directional histogram (42 bins at 8.57-degree increments, accumulated across all keypoints with magnitude weighting).

The two streams are processed through separate small fully-connected networks (63→64→64 and 128→64→64), then fused through a learned softmax-weighted combination:

α = softmax(W_α · concat(v1, v2))
fused = α_1 · v1_out + α_2 · v2_out

The fused 64-dimensional representation is projected to the final 128-dimensional motion embedding. Total parameters: approximately 0.04M.

### 3.3.4 CrossModalFusion: Transformer-Based Modality Integration

The three modality embeddings — visual (512-dim), spatial (256-dim), and motion (128-dim) — represent fundamentally different types of information. Simple concatenation treats them as interchangeable feature channels, missing the opportunity to model cross-modal interactions. The CrossModalFusion module uses a Transformer Encoder to enable each modality to attend to information from the other two modalities.

**Architecture:** Each modality embedding is first projected to a common dimensionality of d_model = 256 through a dedicated linear layer:

V_proj = W_v · V + b_v  (512→256)
S_proj = W_s · S + b_s  (256→256)
M_proj = W_m · M + b_m  (128→256)

The three projected tokens are augmented with **learnable modality type embeddings** — three trainable 256-dimensional vectors E_v, E_s, E_m that encode the source modality of each token:

V_token = V_proj + E_v
S_token = S_proj + E_s
M_token = M_proj + E_m

The three tokens [V_token, S_token, M_token] are concatenated into a sequence of length 3 and processed through a 2-layer Transformer Encoder with h = 8 attention heads, feed-forward dimension d_ff = 1024, and dropout rate 0.1. After cross-modal self-attention, global mean pooling across the 3 token positions produces a unified 256-dimensional fused feature vector.

Learnable modality embeddings enable attention heads to dynamically weight modalities — favoring geometric features under poor lighting where visual features are degraded, and motion features when the hand is moving rapidly. The complete CrossModalFusion module contains approximately 1.9M parameters, the largest single component in the DL pipeline. The parameter distribution reflects the importance of learning cross-modal interactions.

## 3.4 Temporal Modeling Layer: SlowFast TCN with CE Pooling

The temporal modeling layer processes a sequence of T fused feature vectors (one per video frame, each 256-dimensional) and produces a single gesture class prediction for the entire sequence. This is a sequence-to-label mapping: T input frames → 1 output class.

### 3.4.1 Dual-Pathway Design

The SlowFast TCN architecture employs two parallel pathways operating at different temporal resolutions:

**Slow Pathway** (kernel size 7, dilations [1, 2, 4], channel progression [256→64→128→128]):
- Purpose: Capture long-range semantic context spanning complete gesture phrases.
- Receptive field: RF = 1 + (7−1)×(1+2+4) = 43 frames ≈ 1.7 seconds at 25 FPS.
- The 1.7-second window covers: hand entry into the gesture pose (~0.2s), stable hold (1.0–1.5s), and gesture release/transition (~0.2–0.5s) — the complete lifecycle of a single gesture.

**Fast Pathway** (kernel size 3, dilations [1, 1, 2, 2], channel progression [256→32→32→64→64]):
- Purpose: Preserve fine-grained temporal dynamics at high temporal resolution.
- Smaller kernel (3) retains sensitivity to rapid finger movements and brief pose adjustments.
- Lower channel dimensions keep the parameter count minimal.

**Lateral Connections:** After each stage in the Fast pathway, a 1×1 convolution projects Fast features to the Slow pathway's channel dimension and adds them to the corresponding Slow stage. These lateral connections enable the Slow pathway to benefit from the Fast pathway's fine-grained temporal information without increasing its own temporal resolution.

### 3.4.2 Loss Function Design: CE + Temporal Pooling

The choice of loss function is determined by the nature of the recognition task. This system performs **static gesture recognition**: the user holds a single hand pose for each 2-second recording, and the expected output is a single class label. This is a sequence-to-label mapping.

The standard approach is temporal pooling followed by cross-entropy loss:

logits = TCN(features)          # [B, T, C] — per-frame class logits
pooled = mean(logits, dim=1)    # [B, C] — average over time dimension
loss = CrossEntropy(pooled, labels)

The temporal mean pooling operation converts T per-frame predictions into a single sequence-level prediction. Each frame contributes equally to the final prediction, which is appropriate for static gestures where all frames contain the same gesture (the averaging suppresses frame-to-frame noise).

Connectionist Temporal Classification (CTC) [32] was considered but rejected for three reasons: (1) CTC introduces a blank token and learns alignment — unnecessary complexity for single-label prediction; (2) CTC converges less stably on small datasets due to the additional alignment learning task; (3) the additional hyperparameters (blank index, beam width) provide no benefit for static gesture recognition. CE with temporal pooling directly supervises the sequence-level prediction and converges more stably on limited data.

### 3.4.3 Design Rationale: Why TCN Rather Than Transformer

The dominant architecture for sequence modeling in contemporary deep learning is the Transformer. Four considerations drove the choice of TCN: (1) Parameter efficiency — 0.7M versus 10M+ for Transformer, critical on 1,311 samples; (2) Causal convolutions naturally prevent future-frame leakage in real-time inference; (3) Pure convolutional architecture exports cleanly to ONNX for CPU deployment; (4) Receptive field is precisely engineerable (43 frames for 1.7s gesture phrases) through kernel size and dilation configuration.

## 3.5 Rule-Based Recognition Layer: XAI Decision Tree

The rule-based layer provides instantaneous, explainable classifications using a geometric decision tree adapted from clinical goniometric protocols [1][4]. It serves as both a production recognition path with zero parameters and an XAI-compliant fallback when the DL model's reasoning must be auditable.

### 3.5.1 Algorithm Description

The recognition algorithm proceeds through four stages:

**Stage 1 — Finger Extension Classification:** For each finger, the MCP-PIP-DIP angle θ_f is computed. A finger is classified as extended if θ_f > 165°, following the clinical measurement threshold validated by Hamaguchi et al. [4] (criterion validity r = 0.78 for this threshold).

**Stage 2 — Gesture Pattern Matching:** The 5-finger binary state (thumb, index, middle, ring, pinky; 1 = extended, 0 = flexed) forms a 5-bit pattern (32 possible combinations). This pattern is matched against a predefined lookup table mapping to 17 gesture classes. For the Two versus Victory disambiguation, the index-middle fingertip Euclidean distance is computed — a distance below 0.06 normalized units classifies as Two (fingers together), above 0.06 classifies as Victory (fingers spread).

**Stage 3 — PIP/MCP Dual-Channel Verification:** PIP joints are identified in the literature [2][3] as exhibiting the highest MediaPipe tracking error (20–30 degrees deviation). The system performs a secondary check using the more reliable MCP joint angle (Hamaguchi [4]: r = 0.78 for MCP versus r = 0.72 for PIP). When PIP-based and MCP-based finger extension classifications disagree, a 12% confidence penalty is applied.

**Stage 4 — Gesture Classification Output:** The verified 5-bit pattern maps to the final gesture name. PIP-sensitive classes — Victory, Six, Three, Four, Seven, Nine [3] — receive additional scrutiny with stricter confidence thresholds, as their distinguishing features rely on specific finger combinations that are most affected by PIP tracking errors.

### 3.5.2 XAI Compliance

A distinguishing feature of the rule engine is its compliance with Explainable AI (XAI) principles. Every classification decision can be traced to specific, measurable physical quantities:

- "Gesture classified as Closed_Fist because: MCP-PIP-DIP angles for all five fingers were measured below 165 degrees (thumb: 142°, index: 138°, middle: 145°, ring: 151°, pinky: 147°)"
- "Gesture classified as Victory because: Index MCP-PIP-DIP angle = 172° (>165°, extended), Middle MCP-PIP-DIP angle = 168° (>165°, extended), other three fingers all <165° (flexed), index-middle tip distance = 0.12 normalized units (>0.06, separated)"

This traceability is essential for medical triage applications. In a healthcare context, an AI system that cannot explain its decisions faces regulatory and trust barriers. The rule engine's XAI compliance ensures that clinical staff can verify the reasoning by examining the measured joint angles.

## 3.6 Semantic Parsing Layer: Dual-Hand Combinatorial Encoding

The semantic parsing layer represents the core conceptual innovation of this thesis: a protocol that maps a compact vocabulary of 15 gestures to a rich semantic space of 70 slots through combinatorial encoding.

### 3.6.1 Design Philosophy

Traditional sign language recognition maps gestures to meanings in a one-to-one fashion. Real human sign languages achieve far greater efficiency through grammatical composition — handshape, location, movement, and facial expression combine to create meaning beyond the sum of individual components.

The dual-hand combinatorial protocol applies this compositional principle in a simplified, learnable form. The non-dominant (left) hand selects a semantic layer; the dominant (right) hand selects a specific meaning within that layer. With 7 mode gestures and 10 content gestures, the system achieves 70 semantic slots from only 15 base gestures — a 4.7-fold encoding efficiency over one-to-one mapping.

### 3.6.2 Gesture Vocabulary

The 15-gesture vocabulary was designed to satisfy three criteria: (1) gestures must be reliably distinguishable by both the rule engine and the DL model, (2) the finger configurations must be physically comfortable for extended use, and (3) the gesture-to-meaning mapping must be intuitive and learnable.

**Control Gestures (Symmetric Dual-Hand):** Three control functions use symmetric dual-hand gestures held for 0.5 seconds: both hands showing Victory = undo last word, both hands showing Thumb_Down = undo entire sentence, both hands showing One = manual separator between semantic units. ### 3.6.3 SentenceRecorder State Machine

The SentenceRecorder finite state machine governs the recording lifecycle through three states:

- **IDLE:** The system awaits a start trigger. Recording begins via either: (a) a discrete transition from Closed_Fist to Open_Palm on both hands (the natural "preparing to speak" motion), or (b) a sustained hold of both Open_Palm for 1.0 second as a fallback trigger.
- **RECORDING:** Gesture tokens are accumulated under timing constraints: minimum hold duration of 0.3 seconds (to filter transient noise), inter-gesture cooldown of 0.35 seconds, and an idle timeout of 15 seconds after the last accepted gesture. Mode transitions (changing the non-dominant hand gesture) automatically insert a separator token between semantic units. Persistent mode memory retains the last established mode for 1.5 seconds during single-hand tracking loss.
- **OUTPUT:** Triggered by either: (a) sustained both-hands Closed_Fist for 1.5 seconds, or (b) idle timeout of 15 seconds. The accumulated token sequence is sent to the semantic chain parser and DeepSeek for sentence generation. The state machine automatically resets to IDLE after output.

### 3.6.4 Semantic Chain Parser

The TemporalSemanticParser matches the accumulated token sequence against a database of 40 general-purpose semantic chains and 65 hospital-specific medical chains using longest-suffix matching. The parser maintains a sliding buffer of the last 5 tokens with automatic deduplication of consecutive repeats. When the buffer suffix matches a known chain, the parser outputs the chain's category and assembles a base sentence.

For example, the sequence ["疼", "头", "严重"] matches the hospital chain ["疼", "头"] under category "symptom_description", while the trailing "严重" awaits more context or recording end for resolution. If no chain matches, raw token concatenation with comma separators provides a fragmented but informative fallback output.

## 3.7 LLM Enhancement Layer

The LLM enhancement layer transforms raw semantic token sequences into natural, contextually appropriate Chinese sentences, providing two operational modes.

### 3.7.1 Translation Mode

In translation mode, the accumulated gesture token sequence is sent to the DeepSeek Chat API with a hospital communication system prompt. The prompt instructs the model to perform: (1) word reordering — arranging tokens from conceptual order to natural Chinese word order; (2) sentence completion — adding grammatical particles, aspect markers, and cohesive devices; (3) numerical parsing — interpreting number sequences in context; (4) tone customization — adapting the register to the medical context; and (5) dialogue coherence — maintaining consistency with sentence history from previous recordings.

The API call is made synchronously with a connection timeout of 1.5 seconds and a read timeout of 2.0 seconds. If the API does not respond within this window, the system gracefully degrades to the semantic chain parser's base sentence output.

### 3.7.2 Triage Mode

Triage mode extends the translation functionality with interactive multi-turn medical consultation:

1. **Symptom Description:** The patient describes their primary complaint through gestures using the symptom layer (mode=Eight) + body layer (mode=Seven) + severity layer (mode=Two), enabling detailed communication (e.g., "头" + "疼" + "严重" = "severe headache").

2. **LLM Follow-up:** DeepSeek processes the symptom description and generates a closed-ended follow-up question targeting the most diagnostically informative missing information, designed for yes/no answers to accommodate the limited gesture vocabulary.

3. **Patient Response:** The patient answers using the Common Phrases layer (mode=One): Six = "是" (Yes), Nine = "不是" (No).

4. **Iteration:** Steps 2–3 repeat for 2–3 rounds, each targeting a different diagnostic dimension (onset timing, associated symptoms, aggravating/relieving factors).

5. **Department Recommendation:** After confirming no additional symptoms, DeepSeek recommends the most appropriate medical department based on the collected symptom profile.

### 3.7.3 Graceful Degradation

The system implements a four-level graceful degradation strategy:

- **Level 1 (Full Service):** DeepSeek API available → polished natural language output with contextual adaptation.
- **Level 2 (API Timeout):** Semantic chain parser assembles base sentence from matched chains → grammatically simpler but meaningful output.
- **Level 3 (No Chain Match):** Raw token concatenation with comma separators → shows exactly what gestures were recognized.
- **Level 4 (DL/API Failure):** Rule engine only → geometric gesture classification still functions for basic communication.

## 4.1 Dataset Construction

The dataset combines self-collected real samples and synthetic augmentation, as existing public datasets (WLASL [29], MS-ASL, AUTSL) use single-hand annotation schemes incompatible with the dual-hand combinatorial encoding protocol.

### 4.1.1 Real Data Collection

351 real sessions were collected covering 13 gesture classes (Closed_Fist, Eight, Four, Good, Nine, One, Open_Palm, Pinky_Up, Seven, Six, Three, Two, Victory) with 27 samples per class. Each class was recorded under 3 lighting conditions × 3 angles × 3 distances = 27 systematically varied conditions per class. Each 2-second recording yields synchronized keypoint arrays (.npy format) and 96×96 ROI crops (_roi.npy format).

### 4.1.2 Synthetic Data Augmentation

The synthetic data generator produced 960 additional samples (80 per class for 12 classes) with domain randomization simulating challenging conditions identified in the clinical MediaPipe validation literature:

- **Keypoint Jitter:** Gaussian noise (σ = 0.008–0.012 normalized units) added to all 21 keypoint coordinates with 100% probability, calibrated to the 2.46° mean absolute deviation reported by Hamaguchi et al. [4].
- **Finger Occlusion:** 1–5 randomly selected keypoints zeroed per frame (30% probability), simulating partial hand occlusion.
- **Low-Light Simulation:** Jitter magnitude increased to σ = 0.015–0.030 (40% probability), modeling the accuracy degradation under poor lighting conditions documented by Sprague et al. [3].
- **Rotation and Scaling:** Random rotation (±3°) and scaling (±3%) applied to all keypoints (100% probability).

### 4.1.3 Dataset Split

The combined dataset of 1,311 samples (351 real + 960 synthetic) was split using stratified sampling to maintain class balance: training set 70% (906 samples), validation set 15% (196 samples), test set 15% (209 samples).

### 4.2.2 Evaluation Metrics

Classification performance is assessed using standard metrics computed from the confusion matrix:

- **Accuracy (ACC)** = (TP + TN) / (TP + TN + FP + FN)
- **Precision (P)** = TP / (TP + FP)
- **Recall (R)** = TP / (TP + FN)
- **F1-score** = 2 × P × R / (P + R)
- **Macro F1** = unweighted average of per-class F1 scores

For all metrics, 95% Bootstrap confidence intervals are computed from 1,000 resamples of the test set predictions with replacement, following the clinical validation methodology of Wagh et al. [1].

## 4.4 Ablation Study: Modality Contribution Analysis

To quantify the unique contribution of each modality, a systematic ablation study was conducted. Components were removed one at a time from the full pipeline.

**Table 4-5: Ablation Study Results**

| Configuration | Test Accuracy | Δ from Full |
|--------------|---------------|-------------|

The ablation results establish a clear hierarchical dependency:

- **GCN is foundational:** Removal causes catastrophic collapse to 6.2% (near the 7.7% random baseline for 13 classes). Without spatial topology information, the remaining modalities cannot reconstruct the geometric relationships essential for distinguishing hand poses.

- **Motion contributes substantially (31.6 pp):** Despite the task being static gesture recognition, the motion encoder captures subtle within-pose dynamics — hand tremors, finger pressure adjustments, pose stabilization patterns, and micro-movements that characterize individual signing styles — providing discriminative information beyond static spatial features.

- **Visual features provide meaningful augmentation (9.6 pp):** The visual encoder extracts appearance-based cues (skin texture, shadow patterns around flexed joints, hand silhouette) that complement geometric features. The modest contribution relative to motion is consistent with the literature: skeleton-based methods are inherently robust to visual domain shift (background variation, skin tone, lighting), and the frozen MobileNetV3 backbone limits the model's ability to learn task-specific visual features on the limited dataset.

## 4.5 Training Convergence Analysis

The training dynamics provide insight into the model's learning behavior.

**Training loss trajectory:** 2.62 (epoch 1, near the random baseline of ln(13) ≈ 2.56) → 0.15 (epoch 50). The steady monotonic decrease with only minor fluctuations indicates stable training without gradient explosion or vanishing problems, attributable to residual connections in both the GCN and TCN modules and gradient clipping at max_norm=1.0.

**Validation loss** reached its minimum of 0.32 at epoch 37, after which it gradually increased to 0.43 at epoch 50 while training loss continued decreasing to 0.15 — a classic signature of mild overfitting where the model begins to memorize training-set-specific patterns. This is expected behavior given the modest dataset size (906 training samples for a 2.8M-parameter model).

**Validation accuracy trajectory:** 8.3% (epoch 1, random baseline) → 18.2% (epoch 6, start of meaningful learning) → 55.7% (epoch 13, rapid learning phase) → 82.8% (epoch 25) → 90.6% peak (epoch 37) → stabilizing at 85–90% (epochs 37–50).

Two distinct learning phases are observable:

- **Epochs 1–13 (Discrimination Learning):** The model learns to distinguish grossly different hand poses (e.g., closed fist versus open palm). Accuracy rises rapidly from random to above 50%.

- **Epochs 14–50 (Refinement Learning):** The model learns fine-grained distinctions (e.g., Two versus Victory via tip distance, Four versus Nine via ring finger detection). Accuracy climbs more gradually under cosine annealing, which progressively reduces the learning rate to enable finer weight adjustments.

## 4.7 Discussion

### 4.7.1 Rule-DL Complementarity

The rule engine embodies explicit anatomical knowledge (97.6% on idealized synthetic data, 31.1% on real data with anatomical variation). The DL model learns user-specific features from data (82.8% on real data, 51.7pp improvement). This complementarity — rule excels where DL struggles (Closed_Fist 94.1%, Pinky_Up 100%) and DL excels where rule fails (Eight 100%, Good 100%, Nine 100%, Seven 82.4%) — motivates the dual-mode architecture: rule for XAI-guaranteed production in controlled conditions, DL for accuracy-optimized enhancement when user adaptation is needed.

### 4.7.2 Limitations

Several limitations should be acknowledged:

- **Dataset Scale:** 1,311 samples, while carefully constructed with systematic domain randomization, is modest by contemporary deep learning standards and limits the model's ability to learn rare or subtle gesture variations.
- **Single Participant:** The real data was collected from a single participant, and generalization to diverse users with different hand anatomies, signing speeds, and environmental conditions remains to be validated.
- **Challenging Classes:** Open_Palm (41.2%) and Victory (47.1%) need targeted data augmentation or architectural improvements for reliable recognition.
- **No Formal Usability Testing:** Testing has been limited to technical metrics; studies with actual deaf participants are needed to validate the gesture vocabulary ergonomics and communication effectiveness.
- **DL Inference Latency:** The asynchronous 2-second inference delay limits instantaneous feedback, though the rule engine provides immediate (<1ms) alternative results.

### 4.7.3 Scene Transferability

A significant practical contribution is the scene-agnostic architecture. The gesture recognition pipeline (layers 1–4) is completely independent of the application domain. The semantic layer (layers 5–6) is configured through JSON files defining gesture-to-meaning mappings, semantic chain rules, and LLM system prompts. The hospital triage configuration demonstrated in this chapter is one instance; banking, airport information, smart home control, and government services are achievable through configuration file replacement alone — no code modification required.

## 4.8 Chapter Summary

Comprehensive experiments on 1,311 samples (351 real + 960 synthetic) demonstrated: (1) 82.8% DL test accuracy representing a 51.7pp improvement over the rule engine's 31.1% on real user data, with 5-fold cross-validation confirming consistency (84.1% ± 1.5%); (2) ablation results establishing a clear modality hierarchy — GCN spatial topology as foundational (76.6pp), motion dynamics as substantial (31.6pp), and visual texture as complementary (9.6pp); (3) stable training convergence with 90.6% peak validation accuracy at epoch 37 under cosine annealing; and (4) production performance of 31.7 FPS detection speed and 32.1ms processing latency, stable across 92 recording sessions. The complementary relationship between rule-based and DL approaches, with their distinct error patterns, motivates the dual-mode architecture as a practical solution combining XAI compliance with data-driven accuracy.

## 5.3 System Features

The system provides four core features accessible through the web interface.

### 5.3.1 Feature 1: Sign Language Translation Mode

The translation mode workflow: (1) The frontend establishes a WebSocket connection to the FastAPI backend and begins streaming JPEG frames at 25 FPS; (2) the user initiates recording via the both-hands Closed_Fist→Open_Palm transition or a sustained 1.0s Open_Palm hold; (3) gesture tokens are accumulated under 0.3s minimum hold, 0.35s cooldown, and 15s idle timeout, with automatic separator insertion on mode transitions; (4) recording ends via 1.5s Closed_Fist hold or timeout; (5) the token sequence undergoes semantic chain matching and DeepSeek polishing with graceful fallback through four degradation levels.

### 5.3.2 Feature 2: AI Triage Consultation Mode

The triage workflow: (1) The user switches to triage mode via the mode toggle button; (2) the patient describes their primary complaint through gestures (symptom + body + severity layers); (3) DeepSeek generates a closed-ended follow-up question targeting the most diagnostically informative missing information; (4) the patient answers yes/no using the Common Phrases layer; (5) steps 3-4 iterate for 2-3 rounds; (6) DeepSeek recommends the most appropriate medical department with rationale. The conversation runs asynchronously via `run_in_executor`, preventing API blocking of the frame pipeline.

### 5.3.3 Feature 3: DL/Rule Dual-Mode Switching

The system defaults to rule mode on startup (instantaneous, XAI-compliant, zero warm-up). A frontend button toggles between modes. In DL mode, the background daemon thread processes accumulated frames every 2 seconds and updates recognition results asynchronously. Switching modes clears the DL buffer and resets the daemon thread state. Both modes share the same downstream semantic pipeline (SentenceRecorder, semantic chain parser, LLM enhancement).

### 5.3.4 Feature 4: Scene Configuration Migration

The system ships with hospital triage as the default scene. To migrate to a new scene (banking, airport, smart home, government services), the deployer replaces the three JSON configuration files and updates the system prompt. No code modification is required. The gesture recognition pipeline (layers 1–4) remains identical. The SentenceRecorder state machine, semantic parser, and LLM client read their configuration from the JSON files on startup. The mode layer gesture-to-meaning mappings are also scene-configurable — each scene can define its own semantic layers and content slot meanings.

# CHAPTER 6: CONCLUSION AND FUTURE WORK

## 6.1 Conclusion

This thesis presented the design, implementation, and experimental evaluation of a lightweight multimodal real-time sign language recognition system. The system addresses a critical accessibility need — enabling barrier-free communication for deaf individuals in practical daily scenarios — through a carefully engineered pipeline balancing accuracy, efficiency, explainability, and deployability.

The system's core technical contribution is a seven-layer pipeline architecture that converts raw video frames from a commodity RGB camera into natural Chinese sentences. The perception layer achieves 31.7 FPS hand keypoint detection on CPU, exceeding the 25 FPS task book requirement. The feature extraction layer integrates spatial (SpatialGCN with auxiliary angle encoder, 0.15M), visual (LightweightVisualEncoder with frozen MobileNetV3-Small backbone, 0.15M trainable), and motion (MotionEncoder with three-path adaptive fusion, 0.04M) modalities through a Transformer-based CrossModalFusion module (1.9M) with learnable modality type embeddings. The temporal modeling layer employs a SlowFast TCN (0.7M) with carefully engineered receptive fields (43 frames ≈ 1.7 seconds) covering complete gesture lifecycles. The rule-based layer provides XAI-compliant, instantaneous classification with PIP/MCP dual-channel verification derived from clinical literature [2][3][4]. The semantic parsing layer introduces a novel dual-hand combinatorial encoding protocol achieving 4.7-fold semantic efficiency (70 slots from 15 gestures). The LLM enhancement layer integrates DeepSeek API for semantic reassembly and multi-turn triage consultation, with a four-level graceful degradation strategy ensuring system availability under all conditions. The total trainable parameter count of 2.8M represents 72% utilization of the 10M task book budget.

Experimental evaluation on a dataset of 1,311 samples (351 real with ROI capture + 960 synthetic with systematic domain randomization) demonstrated: (1) the multimodal DL model achieving 82.8% test accuracy, representing a 51.7 percentage point improvement over the rule engine's 31.1% on real user data; (2) ablation experiments quantifying modality contributions — GCN spatial topology as foundational (76.6pp), motion dynamics as substantial (31.6pp), and visual texture as complementary (9.6pp); (3) stable training convergence with 90.6% peak validation accuracy at epoch 37 under cosine annealing; and (4) production performance of 31.7 FPS detection speed and 32.1ms processing latency, stable across 92 recording sessions.

It is important to honestly acknowledge the limitations within which these results should be interpreted. The dataset of 1,311 samples, while systematically collected with domain randomization, is modest in scale and derived from a single participant — generalization to diverse users with different hand anatomies, signing speeds, and environmental conditions remains to be validated. No formal usability testing with deaf participants has been conducted, and the reported accuracy represents performance under controlled collection conditions. These limitations are not fundamental flaws but represent the natural boundary between academic prototyping and real-world deployment.

The five key innovations of this work are:

1. **Dual-Hand Combinatorial Encoding Protocol:** A novel interaction paradigm achieving compositional semantics (70 slots from 15 gestures) through the separation of mode (semantic layer selection) and content (meaning specification) across the two hands, with automatic separator insertion and symmetric dual-hand control gestures.

2. **Rule/DL Dual-Mode Complementary Architecture:** The rule engine provides population-level, XAI-compliant, instantaneous (<1ms) recognition with full clinical traceability, while the DL model provides data-driven, user-adaptive recognition (82.8%) that generalizes to individual anatomical variation. Their complementary error patterns motivate coexistence.

3. **Multimodal Lightweight Feature Fusion with Quantitative Validation:** Three encoders spanning spatial (GCN), temporal (motion), and appearance (visual) modalities are fused through a Transformer with learnable modality embeddings at 2.8M total trainable parameters. Systematic ablation experiments provide quantitative evidence for each modality's unique contribution.

4. **Scene-Transferable Architecture:** The gesture recognition pipeline (layers 1–4) is completely scene-agnostic. Semantic mappings, chain rules, and LLM prompts are JSON-configurable, enabling migration across hospital, banking, airport, smart home, and government service scenarios through configuration replacement alone.

5. **Complete Gesture-to-Language Pipeline with LLM Integration:** Beyond isolated gesture classification, the system achieves end-to-end conversion from raw hand movements through semantic parsing to natural language sentences, with an LLM-enhanced multi-turn triage consultation capability.

## 6.2 Future Work

Seven directions for future improvement are identified:

1. **User-Centered Evaluation:** Conduct formal System Usability Scale (SUS) studies with deaf participants to validate gesture vocabulary ergonomics, identify the most comfortable and distinguishable gestures, and measure communication efficiency in realistic scenarios. This is the most critical next step toward real-world deployment.

2. **Multi-User Dataset Expansion:** Collect data from diverse participants spanning different hand sizes, joint flexibility ranges, signing speeds, and skin tones. This would enable training models robust to the full spectrum of anatomical variation, directly addressing the primary limitation of the current single-participant dataset.

3. **Targeted Class Improvement:** Address the challenging classes (Open_Palm 41.2%, Victory 47.1%) through targeted data augmentation — additional samples with controlled variations in finger spread distance and palm orientation — and architectural improvements such as auxiliary classifiers specifically for these ambiguous pairs.

4. **Continuous Sign Language Recognition:** Extend the system from static gesture recognition (one pose, one label) to continuous recognition (dynamic sequences of connected signs). This would require architectural changes: replacing temporal mean pooling CE loss with CTC or sequence-to-sequence modeling, and extending the dataset to include continuous signing sequences with frame-level annotations.

5. **Model Compression for Mobile Deployment:** Apply quantization (INT8), pruning, and knowledge distillation to reduce the model footprint below 1MB for smartphone deployment. The current 2.7MB ONNX model already supports CPU inference, but mobile-grade compression would enable on-device processing without network dependency.

6. **Multi-Modal Sensor Fusion:** Investigate the integration of additional sensing modalities — specifically, a depth camera (RGB-D) for improved 3D keypoint accuracy, and a microphone for complementary speech input from hearing conversation partners — to create a more robust multi-modal communication system.

7. **Long-Term Longitudinal Deployment:** Deploy the system in a real hospital triage setting for an extended period (3–6 months) to collect longitudinal usage data, measure real-world accuracy degradation, identify failure modes, and iteratively improve both the gesture vocabulary and the recognition pipeline based on actual usage patterns.
