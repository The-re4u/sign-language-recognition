### C1：超参数敏感性分析 🟡

**目的**：系统评估关键超参数对模型性能的影响，填补实验章节"缺少超参数搜索"的短板。

**要修改的文件**：`tools/train.py`（支持命令行传参覆盖 config）

**具体操作**（每组独立训练 30 epochs，约 1 小时/组）：

| 实验 | 变量 | 取值 | 预期影响 |
|------|------|------|---------|
| 1 | 学习率 | 1e-3, 1e-4, 1e-5 | 1e-3 可能不收敛，1e-5 收敛慢 |
| 2 | GCN 层数 | 2, 3, 4 层 | 更深可能过拟合（数据量小） |
| 3 | TCN Slow 核大小 | 3, 5, 7 | 更大核 = 更大感受野 |
| 4 | Dropout 率 | 0.1, 0.2, 0.3 | 更高 dropout 可能欠拟合 |
| 5 | Batch Size | 4, 8, 16 | 受 GPU 内存限制 |

**产出**：参数敏感性曲线图（x=参数值, y=Val Acc），补充至论文 3.9 节

**预计耗时**：5 组 × 1h = ~5 小时（可并行跑）

## 七、本地模型替代 DeepSeek 计划

> 目标：训练一个本地轻量化中文大模型，完全替代 DeepSeek API，实现离线推理。
> 当前 DeepSeek 承担的 4 项功能全部需本地化。

### 现状分析

| 功能 | DeepSeek 方法 | 输入 → 输出 | 调用位置 |
|------|-------------|------------|---------|
| 翻译组装 | `reorder_and_assemble()` | 手势 token 列表 → 自然中文句子 | `sentence_recorder._parse_sequence()` |
| 句子润色 | `hospital_polish()` | 粗糙中文句子 → 流畅中文句子 | `sentence_recorder._parse_sequence()` |
| 通用增强 | `enhance()` | 手势 token 列表 → 自然中文句子 | 备用（当前未调用） |
| 导诊对话 | `triage_conversation()` | 患者症状描述 → 追问/科室推荐 JSON | `server.py` WebSocket handler |

### 方案选择

**推荐方案**：Qwen2.5-1.5B-Instruct + QLoRA 微调 + llama.cpp CPU 推理

| 对比维度 | Qwen2.5-1.5B | Qwen2.5-0.5B | ChatGLM3-6B |
|---------|-------------|-------------|-------------|
| 中文能力 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐ |
| 模型大小 | 3.1 GB (FP16) | 1.0 GB (FP16) | 12 GB (FP16) |
| QLoRA 训练显存 | ~4 GB | ~3 GB | ~8 GB |
| CPU 推理速度 | ~5-8 token/s | ~10-15 token/s | ~1-2 token/s |
| 医疗知识 | 需微调注入 | 需微调注入 | 有一定基础 |
| 开源协议 | Apache 2.0 | Apache 2.0 | 非商用 |

### 阶段一：训练数据构建（答辩后启动）

| # | 任务 | 具体操作 | 预计耗时 | 状态 |
|---|------|---------|---------|------|
| L1 | **收集 DeepSeek 历史响应** | 在现有系统运行时，记录所有 DeepSeek API 的输入-输出对（tokens→sentence, rough→polished, symptom→follow-up），保存为 JSONL。目标：**500+ 对**覆盖翻译，**200+ 对**覆盖导诊 | 边用边积累 | ⬜ |

| L3 | **数据增强** | 基于 65 条医院语义链 + 40 条通用语义链，程序化生成变体训练样本（同一手势序列的不同 token 顺序、不同严重程度组合等） | 1天（写脚本+运行） | ⬜ |

### 阶段二：模型微调

| # | 任务 | 具体操作 | 预计耗时 | 状态 |

### 关键技术栈

| 组件 | 选型 | 用途 |
