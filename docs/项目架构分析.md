### 核心设计：双模式并行识别（DL/规则可切换）

```
输入帧 (WebSocket JPEG, 25fps)
        │
        ├──→ [规则模式] RuleRecognizer ──→ 17种手势 ──┐
        │                                               │
        ├──→ [DL模式] SpatialGCN + MotionEncoder       ├──→ SentenceRecorder
        │   + CrossModalFusion + SlowFastTCN (ONNX)     │       │
        │                                               │       ▼
        └──→ 前端按钮一键切换 DL/规则 ←─────────────────┘   语义解析器
                                                               │
                                                               ▼
                                                         DeepSeek润色 → 句子输出

两种模式通过前端按钮一键切换。DL模式每60帧(~2.4s)进行一次ONNX推理，
规则模式逐帧运行。模式手与内容手为互斥集合，零歧义。
```

## 四、核心算法详解

### 4.1 空间编码 — SpatialGCN（图卷积网络）

**文件**: `core/feature/spatial_gcn.py`

```
输入: [B, 21, 3]  归一化关键点坐标
输出: [B, 256]    空间拓扑特征
参数: ~0.15M
```

- 将 21 个手部关键点建模为**图结构**（骨骼边 19 条 + 功能边 4 条 → 46 条无向边）
- **3 层 GraphConvLayer** + 残差连接 → 全局均值池化
- 额外编码 **10 个关节角度** + **5 个手指伸展比** 作为几何先验
- 最终融合：GCN特征(256) + 角度特征(64) → FC → 256

### 4.2 运动编码 — MotionEncoder

**文件**: `core/feature/motion_encoder.py`

```
输入: flow_hist [B, 128] + keypoint_diff [B, 63] + kinematic_vec [B, 17]
输出: [B, 128] 运动特征
参数: ~0.04M
```

- **光流直方图**（128 维）：Farneback 稠密光流 → 幅度 + 方向直方图
- **关键点速度场**（63 维）：21x3 逐帧差分
- **运动学特征**（17 维）：手掌速度 + 指尖速度 + 协调性变化 + 轨迹稳定性
- **自适应融合**：3 路 Learned Softmax 权重加权拼接

### 4.3 多模态融合 — CrossModalFusion（Transformer）

**文件**: `core/feature/multimodal_fusion.py`

```
输入: Visual [B, 512] + Spatial [B, 256] + Motion [B, 128]
输出: [B, 256] 融合特征
参数: ~1.9M
```

- 3 路特征各自投影到 d_model=256
- **可学习模态类型嵌入**（Modality Embedding）区分不同模态
- 拼接为 3 个 token → **2 层 Transformer Encoder**（8 头注意力）做跨模态交互
- 全局均值池化 → 输出投影

### 4.4 时序建模 — SlowFast TCN（双路径时序卷积）

**文件**: `core/temporal/slowfast_tcn.py`

```
输入: [B, T, 256] 融合特征序列
输出: [B, T, num_classes] 逐帧 logits
参数: ~0.7M
```

**双路径设计**：

| 特性 | Slow Path | Fast Path |
|------|-----------|-----------|
| 卷积核 | 7（大核） | 3（小核） |
| 膨胀率 | [1, 2, 4] | [1, 1, 2, 2] |
| 通道数 | [256-64-128-128] | [256-32-32-64-64] |
| 语义 | 长程上下文 | 细粒度动态 |

**横向连接**：Fast → Slow 通过 1x1 卷积跨路径信息传递。

### 4.5 可解释手势判定树（XAI，生产主路径）

**文件**: `core/fallback/rule_recognizer.py`

医疗场景对算法透明性有严格要求。本系统将手势识别形式化为**基于临床运动学先验的确定性决策树**，
每步判定均可追溯到具体关节角度与解剖学约束，满足可解释AI（XAI）框架：

```
关键点坐标 (21×3)
        │
        ├─→ [特征提取] 首帧手腕归一化 + 手掌尺寸缩放
        │       归一化公式: kp' = (kp - wrist) / ‖middle_mcp - wrist‖
        │
        ├─→ [手指伸展判定] MCP/PIP 关节角度计算 (a-b-c)
        │       ├─ > 165° → 伸展  (基于临床运动学阈值, Hamaguchi 2024)
        │       └─ ≤ 165° → 屈曲
        │
        ├─→ [双通道校验] PIP 检测 + MCP 辅助检测
        │       ├─ PIP 通道: Maggioni (2025) 报告误差 20-30°, Sprague (2025) 确认高速退化
        │       └─ MCP 通道: 更可靠 (Hamaguchi 2024: r=0.78 vs PIP r=0.72)
        │       两通道一致率 < 100% → 置信度递减 (每不一致指 -12%)
        │
        ├─→ [手掌朝向] 拇指方向角 + 手腕-无名指方向角
        │       └─ 区分 Good(拇向上, <30°) / Thumb_Down(拇向下, >30°)
        │
        └─→ [分类决策] 模式/内容双集合互斥 (6模式 ∩ 10内容 = ∅)
                └─ 17种手势零歧义判定
```

**可解释性保证**：每个分类结果可反向追溯到 (1) 具体关节角度值 (2) 判定阈值依据 (3) 置信度扣分原因。
与黑盒 DL 模型相比，该方案满足 ISO 13485 医疗软件对算法透明性的监管要求。参数统计：0M（无需训练）。

### 4.6 语义链解析 — TemporalSemanticParser

**文件**: `core/semantic/temporal_parser.py`

```
手势Token流 → 滑动窗口缓冲 (deque, maxlen=5)
                    │
                    ├→ 标准化 (同义词映射)
                    ├→ 去重 (连续重复合并)
                    ├→ 最长后缀匹配 (40+条通用链 + 65条医院链)
                    ├→ 贪心策略 (优先最长链，允许前缀噪声)
                    ├→ 延期机制 (缓冲区可能是更长链前缀时等待)
                    │
                    └→ 输出: {chain, category, priority}
```

### 4.7 句子级记录器 — SentenceRecorder（v3.0 核心创新）

**文件**: `core/semantic/sentence_recorder.py`

**双手组合编码协议**：7 语义层 x 10 内容手势 = 70 个基础语义槽位（v3.4 每层 10 槽，数字层完整 0-9）

**对称双手控制**（v3.2 修正）：

| 功能 | 双手手势 | 说明 |
|------|---------|------|
| 开始录制 | 握拳→张开 (过渡) | 或双手 Open_Palm 持续 1.0s |
| 结束录制 | 张开→握拳 (过渡) | 或双手 Closed_Fist 持续 1.5s |
| 分隔符 | 双手 Space | 允许连续相同手势输入 |
| 撤销词 | 双手 Good | 删除上一个手势词 |
| 撤销句 | 双手 Victory | 清空全部 buffer |

## 七、推理时流水线

```
摄像头帧 (320x240 JPEG, 25fps) 或 上传视频
        │
        ▼
    WebSocket 接收 → JPEG解码 → 降采样160px
        │
        ├→ MediaPipe HandLandmarker 检测 → 21关键点 + handedness
        │
        ├→ [规则模式] RuleRecognizer.recognize_with_confidence()
        │       └→ 手指状态 + 手势名 + 置信度 + PIP补偿
        │
        ├→ [DL模式] SpatialGCN + MotionEncoder + Fusion → ONNX TCN
        │       └→ 每60帧推理一次 → 手势类别 + 置信度
        │
        ├→ KinematicFeatures (手掌速度/轨迹稳定性)
        │
        ├→ SentenceRecorder.process()  → 句子级状态机
        │       ├─ 'start'      UI: "开始记录 - 做手势输入"
        │       ├─ 'buffer'     UI: "记录中: 疼 → 头 → 持续"
        │       └─ 'output'     UI: 自然语句 + DeepSeek润色
        │
        └→ WebSocket JSON 响应 → 前端渲染
            {
              fps, detect_ms, proc_ms,
              hands: [{label, gesture, landmarks, confidence}],
              semantic: {action, text, buffer, state},
              use_dl, dl_gesture, dl_confidence
            }
```

**FPS 优化策略**（v3.2）：
- 输入降采样至 160px（MediaPipe 推理提速 ~30%）
- input_skip=2（隔帧处理，管道不积压）
- FPS 按输入帧率统计（稳定 ~25fps）
- proc_ms 单独显示实际处理耗时（透明监控）

## 八、SlowFast TCN + CE 选型论证

### 为什么选择 SlowFast TCN 而非 Transformer？

| 维度 | SlowFast TCN | Transformer | 选择理由 |
|------|-------------|-------------|---------|
| 参数量 | 0.7M | 10M+ (ViT-B) | TCN 参数量远低于 10M 任务书限制 |
| 实时性 | 因果卷积，无未来帧泄漏 | 需因果掩码 | 手语识别是实时任务，TCN 天然因果 |
| 训练数据需求 | 数千样本可训练 | 通常需万级样本 | 手语数据集规模有限 |
| 推理速度 | 纯卷积，ONNX 友好 | 自注意力 O(T²) | 边端部署更友好 |
| 多尺度建模 | SlowFast 双路径 | 需额外设计 | Slow 路径捕获长程语义，Fast 保留细粒度 |
| 感受野 | 可精确控制（膨胀卷积） | 全局（但需掩码） | 1 秒手势对应 ~25 帧，TCN 感受野 ~28 帧刚好覆盖 |

Slow Path（大核7 + 膨胀[1,2,4]）感受野 = 1 + (7-1)×(1+2+4) = 43 帧 ≈ 1.7 秒，覆盖完整手势短语。
Fast Path（小核3 + 膨胀[1,1,2,2]）保留手指细粒度动态信息。

### 为什么使用 CE + 时间池化而非 CTC？

本系统的任务是**序列→单标签分类**：用户保持同一个静态手势 2-3 秒，系统输出一个手势类别。这与连续手语识别（一段视频→多手势序列）有本质区别。

| 维度 | CE + 时间均值池化（本系统） | CTC |
|------|--------------------------|-----|
| 任务类型 | Sequence → Label（T 帧 → 1 类别） | Sequence → Sequence（T 帧 → L 标签） |
| 对齐需求 | 不需要（全序列同一标签） | 需要学习帧-标签对齐 |
| blank token | 不需要 | 必须引入 |
| 输出 | 单个类别 logits | 逐帧 logits + 合并/解码 |
| 训练稳定性 | 直接监督，稳定收敛 | 需平衡 blank/非 blank 比例 |
| 适用场景 | 静态手势逐次识别 | 连续手语序列识别 |

T 帧特征通过 TCN 输出 `[B, T, C]` logits，沿时间维取均值池化得到 `[B, C]`，直接送入交叉熵损失。该设计将时序建模与分类解耦——TCN 负责帧间特征聚合，均值池化消除帧数差异，CE 提供稳定监督信号。

**CTC 的适用场景**：若未来系统升级为连续多手势识别（用户连续做"你好→我→不舒服"，从一段长视频中输出手势序列），CTC 或其变体（RNN-T、LAS）将是合适的损失函数。当前 SentenceRecorder 状态机已将连续输入拆分为逐手势处理，CE 是更简洁高效的选择。

### 为什么需要规则兜底？

DL 模型精度依赖训练数据分布。临床场景中手势角度、光照、手型差异大，纯 DL 泛化不足。规则引擎（几何方法）：
- 零样本：无需训练，直接用关节角度判定
- 可解释：每个分类结果可追溯到具体关节角度
- 确定性：相同输入永远相同输出
- 低延迟：纯数值计算，< 1ms

DL/规则双模式互补——DL 处理常见手势，规则覆盖边界情况。

## 九、设计亮点（续）

1. **双模式识别可切换**
   - 规则模式：逐帧运行，零延迟，生产主路径
   - DL 模式：周期性 ONNX 推理，2.8M 参数模型
   - 前端按钮一键切换，无需重启服务

2. **多层降级策略**
   - 深度学习 (ONNX) → 规则引擎 (几何) → 裸 Token 拼接
   - 任何一层挂掉系统都能正常工作

3. **手势→语义→自然语言的完整闭环**
   - 不是简单的分类器，而是将手势作为语言 token
   - 40+ 通用链 + 65 条医院链支持多级表达

4. **对称双手控制（v3.2 修正）**
   - 双手同一手势触发控制，与正常模式+内容输入完全无歧义
   - 无需额外交互设备

5. **Web 前端架构**
   - Vue3 + WebSocket + FastAPI，无需安装客户端
   - 支持摄像头实时识别 + 上传视频测试
   - Canvas 骨架渲染 + 实时性能监控

6. **生产级细节**
   - 防误触（最短持续时间 0.3s、冷却期 0.35s）
   - GPU delegate 优先 → CPU 自动降级
   - 隔帧处理策略防管道积压
   - 状态机完整重置（防跨会话泄漏）

7. **场景可迁移架构**
   - 语义映射层通过 JSON 配置，非硬编码
   - DeepSeek Prompt 按场景定制（医院/银行/机场）

8. **临床级验证套件**
   - 13 项验证测试 + Bootstrap 置信区间 + ECE 校准
   - **主要方法论文献**：Wagh et al. (2025) [1] — 首次验证单摄像头 MediaPipe 可提取临床级运动学指标（手掌速度/BVE），为本系统运动学特征层的设计提供了直接方法论依据
